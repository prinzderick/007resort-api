# R007.Infrastructure

Placeholder for persistence and external integrations (MySQL access, outbox, sync transport,
payment/SMS/email gateways, printers exposed via the API, etc.). **No persistence code yet** — the
data-access approach is pending architecture (ADR) review.

## Database rules (binding once implementation starts)

- **Engine:** MySQL **8.4 LTS**, **InnoDB** only, `utf8mb4` / `utf8mb4_0900_ai_ci`.
- **Ownership:** this repository (`007resort-api`) is the *only* owner of the schema. Clients (POS, KDS,
  web, mobile) never connect to MySQL directly and never ship their own migrations.
- **Money:** `decimal` in C#, `DECIMAL(19,4)` in MySQL. Never `float`/`double`. Currency stored
  explicitly (ISO 4217) where amounts can be in more than one currency.
- **Time:** all timestamps are UTC (`DATETIME(6)` holding UTC, or `TIMESTAMP` where appropriate);
  use `IClock` — never `DateTime.Now`. Local time is a presentation concern only.
- **Identifiers:** sync-sensitive records use UUIDs generated by the application (UUIDv7 preferred
  for index locality), stored as `BINARY(16)`. Auto-increment keys are allowed only for purely
  local, never-synced lookup data.
- **Financial records** (payments, invoices, stock movements, ledger entries) are immutable:
  corrections are new reversal/adjustment records, never `UPDATE`/`DELETE`.
- **Concurrency:** optimistic concurrency (row version) on mutable aggregates.
- **Idempotency:** mutating endpoints accept an idempotency key; the key store lives here.
- **Audit:** sensitive actions write to the audit log in the same transaction.

Migrations live in [`/db/migrations`](../../db/migrations/README.md).
